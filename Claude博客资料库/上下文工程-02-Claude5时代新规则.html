🎯 一句话

模型能力提升之后，很多过去的提示词技巧不再必要，甚至有害。⭐ 核心变化：从「手把手教它怎么做」转向「说清目标和边界，让它自己规划」。

Claude 5 代模型需要与早期版本根本不同的上下文工程方法。Anthropic 把 Claude Code 的系统提示词削减了 80% 以上而性能不降——新一代模型需要的是更少的显式约束和更多的自主判断空间。

「解开束缚」（Unhobbling Claude）

  • 过去在系统提示词、CLAUDE.md、skills 中堆积的相互冲突的指令实际上在过度约束模型
  • Claude 5 代模型能自行理解用户意图、做出更好的判断，不需要反复设置护栏防错
  • 新工具（memory、artifacts、skills）取代了过去对 CLAUDE.md 作为唯一信息库的依赖

六大范式转变（Then → Now）

# 过去（Then） 现在（Now）
1 写显式规则（如「永远不要写多段 docstring」） 信任 Claude 参照周围代码风格自行判断
2 为工具提供使用示例 设计有表达力的工具接口和参数，自然引导探索
3 把所有指导塞进初始系统提示词 通过 skills 和延迟加载工具按需战略性加载上下文
4 在系统提示词和工具描述里重复指令 工具指导放进工具描述，消除冗余
5 手动热键更新 CLAUDE.md 自动保存相关工作上下文到记忆
6 用简单 markdown 文件写计划/规格 用 HTML artifacts、测试套件、代码样例做丰富的参照物

上下文组装框架

  • 系统提示词： 产品上下文和 Agent 身份（用户很少改动）
  • CLAUDE.md： 轻量的仓库概览，聚焦「不明显的坑」而非显而易见的事实；复杂指导用渐进式披露
  • Skills： 编码团队专属知识和最佳实践的轻量聚焦指南；除关键领域外避免过度约束
  • References： 用 @ 引用深度规格；优先用基于代码的参照（测试套件、mockup）而非文字描述

具体例子

  • Todo 工具用状态枚举（pending / in_progress / completed）隐式引导 Claude 的用法，无需显式示例
  • Claude 现在能处理越来越复杂的参照物：HTML artifact、详细测试套件都可以作为规格格式

建议

  1. 用 claude doctor 命令系统性地简化系统提示词、skills 和 CLAUDE.md
  2. 移除旧方法里过度限制性的规则，信任模型判断
  3. 用渐进式披露分层组织信息，按需加载
  4. 精心设计接口而非依赖示例
  5. 规格优先用代码形式的参照物而非文字描述

文末指引读者参阅 Fable field guide 获取针对高级模型的更多提示词策略。

✅ 检查点

  1. 模型变强后，哪一类提示词技巧变得不必要甚至有害？
  2. 新的重心应该放在哪里？
  3. 为什么过度指定步骤反而会降低效果？
👀 答案
  1. 把任务拆成固定步骤、手把手规定每一步怎么做这一类。过去模型规划能力弱，需要人替它拆解；现在过度拆解反而限制了它找到更好路径的空间。
  2. ⭐ 说清三件事：目标是什么、边界在哪、怎么算做完了。也就是把重心从「过程指令」转向「目标与验收标准」。同时把力气花在提供正确的上下文和工具上，而不是雕琢措辞。
  3. 因为你给的步骤是基于你的假设写的，而模型看到的实际情况可能不同。当实际情况和你的假设不符时，模型会在「遵守你的步骤」和「解决实际问题」之间摇摆，结果两头都不讨好。⭐ 说清目标反而让它能根据实际情况调整路径。
