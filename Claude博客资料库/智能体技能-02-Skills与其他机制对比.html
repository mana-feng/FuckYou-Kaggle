🎯 一句话

提示词、工具、MCP、Skills 解决的是不同问题。⭐ 一句话区分：提示词说「怎么想」，工具给「能做什么」，MCP 是工具的接入协议，Skills 打包「某类任务的完整做法」。

Claude 的 Agent 生态由五个互补组件构成——Skills、提示词、Projects、子 Agent、MCP——各有分工。理解何时用哪个，才能搭出兼具专业能力、持久知识与工具连接的复杂工作流。

Skills vs 提示词（Prompts）

  • Skills： 持久、可复用的程序性知识，跨对话动态加载；采用渐进式披露——先加载约 100 token 的元数据，相关时才加载 <5K token 的完整指令
  • 提示词： 会话内的一次性自然语言指令，不跨会话持续
  • 切换时机： 反复输入类似指令（如「按 OWASP 标准审查这段代码的安全漏洞」）就是创建 Skill 的信号

Skills vs Projects

  • Projects： 自包含的工作空间，承载持久上下文——文档、知识库、定制指令；200K 上下文窗口，RAG 模式下可扩展至 10 倍
  • Skills： 按需激活的动态专长，节省上下文窗口
  • 关键区分： Projects 回答「你需要知道什么」；Skills 回答「怎么做事」。参考资料（市场研究、竞品分析、产品规格）放 Projects；程序性知识和可执行代码放 Skills

Skills vs 子 Agent（Subagents）

  • 子 Agent： 独立的 AI 助手，有隔离的上下文窗口、定制系统提示词、受限工具权限；自主处理离散任务后返回结果
  • Skills： 可移植的专长，任何 Agent 实例都能取用
  • 策略： 多个 Agent 需要相同专长（安全审查流程、数据分析方法）→ Skills；需要独立任务执行 + 特定工具限制 + 上下文隔离 → 子 Agent；两者可组合——子 Agent 可以调用 Skills 应用专门方法论

Skills vs MCP

  • MCP： 连接外部数据源和工具（Google Drive、Slack、GitHub、数据库、私有系统）的标准化通道
  • Skills： 教 Claude 有效使用这些连接工具的程序性知识
  • 互补关系： MCP 让 Claude 接入外部系统，Skills 教 Claude 如何用好那些数据。例：MCP 连上公司数据库，Skill 教最优查询模式（「查询我们的数据库时永远先按日期范围过滤」）

具体案例

品牌规范 Skill

包含公司色板、字体规则、版式规范。Claude 制作演示文稿或文档时自动应用这些标准，无需每次重复解释。

竞争情报工作流（五件套协同）

  1. Project： 上传行业报告、竞品文档、客户反馈、历史研究
  2. MCP： 连接 Google Drive（共享研究文档）、GitHub（竞品仓库）、Web 搜索（实时数据）
  3. Skill： competitive-analysis 技能提供组织文件系统内的结构化搜索策略
  4. 子 Agent： market-researcher（Read/Grep/Web-search 工具）+ technical-analyst（Read/Bash/Grep 工具）并行执行
  5. 提示词： 对话式微调方向

一个请求（「分析前三名竞品如何定位 AI 功能并找出可利用的缺口」）触发全套协同：Project 上下文加载 → MCP 连接激活 → Skill 框架介入 → 子 Agent 并行 → 提示词细化。

建议

  1. 评估持久性： 反复用的专长 → Skills；一次性指导 → 提示词；跨对话持续上下文 → Projects
  2. 评估范围： 提示词管眼前；Skills 保证跨对话一致；Projects 按主题组织多个对话；子 Agent 隔离专门任务；MCP 连接外部系统
  3. 分层组合： 「Projects 说这是你需要知道的；Skills 说这是做事的方法」
  4. 渐进式成长路径： 从 Projects + 提示词开始 → 指令跨 Project 重复时提炼成 Skills → 流程复杂时引入带工具限制的子 Agent → 需求扩展时用 MCP 接入外部数据

✅ 检查点

  1. 四种机制各自解决什么问题？
  2. Skills 和「把说明写进系统提示词」有什么区别？
  3. 什么时候该做成 Skill 而不是工具？
👀 答案
  1. 提示词：塑造模型的思考方式和风格；工具：赋予它与外部世界交互的能力；MCP：工具的标准接入协议，解决「怎么把工具接进来」；Skills：把「某类任务该怎么做」连同资源和验证方式打包成一个可复用单元。
  2. ⭐ 关键区别是加载时机：系统提示词每次都占上下文，不管这次用不用得上；Skills 是按需加载的——模型先看到一句简短描述，判断相关才展开完整内容。这让你能挂几十个 Skill 而不撑爆上下文。
  3. ⭐ 当你要传授的是「一套做法」而不是「一个动作」时。工具适合原子操作（查天气、写文件）；Skill 适合多步骤、有约定、有验收标准的完整流程（如「按本公司规范生成一份季度报告并校验格式」）。

🛑 可以停在这里

先记住这几件事

  • 工具提供动作，MCP 负责接入，Skill 打包一类任务的做法。
  • 是否常驻与何时加载，是不同引导方式的重要区别。
  • 传授多步骤流程用技能，确定性权限与执行约束放到系统机制中。
