04 · 视图还是拷贝

⏱ 106 分钟 ｜ ⭐ 两行只差一对方括号的代码，一行把原数组改了，一行没有 —— 而 NumPy 两次都没吭声

🎯 一句话

NumPy 的很多操作返回的不是新数据，是「同一块内存的另一种读法」。改了它，原数组跟着变 —— 不报错、不警告，唯一可靠的判据是 np.shares_memory(a, b)。

上一章那类错误至少还留了点痕迹：要么 ValueError，要么结果形状变成一张莫名其妙的方阵。 这一章是完全没有信号的那一类：程序跑通了、形状对、数字看着也合理， 只是你的输入数据在中途被人改掉了。

先观察：两种读取，两种结果

先预测 b 会不会变，再运行第一段代码核对。

🧩 一、两行只差一对方括号

import numpy as np

b = np.arange(6)
c = b[::2]          # 基础切片
c += 1
print("c = b[::2];   c += 1   ->  b =", b)

b = np.arange(6)
c = b[[0, 2]]       # 花式索引（整数数组）
c += 1
print("c = b[[0,2]]; c += 1   ->  b =", b)

b = np.arange(6)
print()
print("np.shares_memory(b, b[::2])   =", np.shares_memory(b, b[::2]))
print("np.shares_memory(b, b[[0,2]]) =", np.shares_memory(b, b[[0, 2]]))

切片后改 cc = b[::2]; c += 1 -> b = [1 1 3 3 5 5]
花式索引后改 cc = b[[0,2]]; c += 1 -> b = [0 1 2 3 4 5]
切片是否共享np.shares_memory(b, b[::2]) = True

⭐ 两行代码长得几乎一样，一行动了 b，一行没动。

  • b[::2] 给的是视图 —— c 和 b 是两个不同的 Python 对象，但指着同一块内存。 c += 1 就地改那块内存，b 当然跟着变。
  • b[[0, 2]] 给的是拷贝 —— 数据被抄了一份出来，改 c 和 b 没关系。

⚠️ 两行都不报错，都返回一个正常的数组。 差别不在语法、不在形状、不在类型， 只在「返回的东西背后是不是同一块内存」。

⚠️⚠️ 先别急着总结成「花式索引不会改原数组」 —— 第四节会给你一个反例， 那是本章最容易记反的一条。这里成立的只有一句话：b[[0,2]] 这次【读】回来的东西是拷贝。

怎么判断是否共享内存

判据说明和完整写法表放在一起；.base 回答的不是同一个问题。

🔍 二、判据：np.shares_memory，不是 .base

结论先放这儿，这一行你会用一辈子：⭐ np.shares_memory(a, b) —— 唯一在所有情况下都对的判据。

.base 看起来更直观 —— 视图有 base、拷贝没有 —— 而且在最简单的情形下它确实对：

import numpy as np

# 情形一：源数组自己就是内存的持有者
b = np.arange(6)
c = b[::2]
print("b 自己持有内存吗  b.base is None :", b.base is None)
print("c.base is b                     :", c.base is b)

# 情形二：源数组本身也是个视图
base = np.arange(12)
a = base.reshape(3, 4)
print()
print("a.base is base                  :", a.base is base)
print("a.T.base is a                   :", a.T.base is a, "  <- 直觉会以为 True")
print("a.T.base is base                :", a.T.base is base)
print("np.shares_memory(a, a.T)        :", np.shares_memory(a, a.T))

# 拷贝的 .base
print()
print("a[[0, 2]].base                  :", a[[0, 2]].base)
print("a.copy().base                   :", a.copy().base)
print("np.shares_memory(a, a.copy())   :", np.shares_memory(a, a.copy()))

⭐ c.base is b 那一行是对的，但它有前提：b = np.arange(6) 自己就是那块内存的持有者 （b.base is None）。一旦源数组本身也是个视图，这个写法就开始骗你。

⚠️ 两个方向都会错，所以 .base 不能当判据：

错法 实测 为什么
共享内存，却判成「不是视图」 a.T.base is a → False .base 不指向上一层，直接指向最终持有那块内存的数组（a.T.base is base 才是 True）
不共享内存，却判成「是视图」 见下 有些操作会先偷偷拷一份，返回的东西 .base 指向那份临时拷贝，而不是你手里的 a

第二条在第三节的表里有两个现成的例子（a.T.reshape(12) 和 a[1:3, [0, 2]]）： 它们的 .base 不是 None，但 np.shares_memory(a, ...) 是 False。 所以 if x.base is not None: # 那它是个视图 这个写法会在两个方向上都出错。

⭐ 第一条的完整机制在 05 章第三节，那里把「视图的视图」这一层讲透了。 这一章只要你记住结论：判共享内存，一律写 np.shares_memory。 ⚠️ 它在超大数组上可能偏慢，替代品和取舍也在 05 章第三节。

读取结果是拷贝，不等于不能写回原数组

把“先取出来再改”和“直接给下标赋值”分清。

💀 四、最容易记反的一条：b[[0,2]] += 1 会改原数组

第一节说「花式索引给的是拷贝」。很多人由此推出「所以花式索引改不了原数组」—— 这是错的。

import numpy as np

# ① 先取出来，再改那个取出来的东西 —— 花式索引给的是拷贝，原数组不动
b = np.arange(6)
c = b[[0, 2]]
c += 1
print("① c = b[[0,2]]; c += 1     ->  b =", b, " c =", c)

# ② 直接对下标做增量赋值 —— 走的是 __setitem__，写回去了
b = np.arange(6)
b[[0, 2]] += 1
print("② b[[0,2]] += 1            ->  b =", b)

# ③ 显式赋值，当然也写回去
b = np.arange(6)
b[[0, 2]] = 99
print("③ b[[0,2]] = 99            ->  b =", b)

# ④ 布尔索引一模一样
b = np.arange(6)
d = b[b % 2 == 0]
d += 100
print("\n④ d = b[b%2==0]; d += 100  ->  b =", b, " d =", d)

b = np.arange(6)
b[b % 2 == 0] += 100
print("⑤ b[b%2==0] += 100         ->  b =", b)

实跑输出：

实验结果：逐项核对，不是执行步骤
观察项原样结果与说明
先读拷贝再改① c = b[[0,2]]; c += 1 -> b = [0 1 2 3 4 5] c = [1 3]
直接增量写回② b[[0,2]] += 1 -> b = [1 1 3 3 4 5]
直接赋值③ b[[0,2]] = 99 -> b = [99 1 99 3 4 5]
先读布尔结果再改④ d = b[b%2==0]; d += 100 -> b = [0 1 2 3 4 5] d = [100 102 104]
直接布尔下标写回⑤ b[b%2==0] += 100 -> b = [100 1 102 3 104 5]

⭐ 判据是「那个下标在不在等号左边」，和视图还是拷贝是两件独立的事：

你写的 Python 实际调用的 会不会改 b
c = b[[0,2]]，之后改 c b.__getitem__([0,2]) —— 抄一份给你 ❌ 不会
b[[0,2]] += 1 b.__setitem__(...) —— 按下标直接往 b 里写 ⭐ 会
b[[0,2]] = 99 同上 ⭐ 会

⚠️ 还有第三种，最阴：下标不在等号左边、但看起来像在：

import numpy as np

# ① 链式下标 + 基础切片：中间那步是视图，写得进去
a = np.arange(12).reshape(3, 4)
a[0][1] = 99
print("① a[0][1] = 99        -> a[0] =", a[0], " ✅ 写进去了")

# ② 链式下标 + 花式索引：中间那步是【拷贝】，写完就被丢掉
a = np.arange(12).reshape(3, 4)
a[[0, 1]][0] = 99
print("② a[[0,1]][0] = 99    -> a[0] =", a[0], " ❌ 一声不吭，什么也没发生")

# ③ 布尔索引同理
a = np.arange(12).reshape(3, 4)
a[a > 5][0] = 99
print("③ a[a>5][0] = 99      -> a.ravel()[6] =", a.ravel()[6], " ❌ 同样没发生")

# ④ 正确写法：一次写完，别分两步
a = np.arange(12).reshape(3, 4)
a[[0, 1], 0] = 99
print("④ a[[0,1], 0] = 99    -> a[:, 0] =", a[:, 0], " ✅")

a = np.arange(12).reshape(3, 4)
a[a > 5] = 99
print("⑤ a[a>5] = 99         -> a.ravel()[6] =", a.ravel()[6], " ✅")

💀 a[[0,1]][0] = 99 是本章最坏的一种失败：它既不报错、也不生效。 a[[0,1]] 先当作 __getitem__ 跑完，造出一份临时拷贝，[0] = 99 写进那份拷贝， 然后临时拷贝当场被回收。你写的那一行，效果等于什么都没写。

⭐ 一句话记法：只有【紧挨着等号左边】的那个下标才是写；它左边的每一步都是读。 a[0][1] = 99 之所以生效，是因为读那一步 a[0] 恰好给的是视图。语法一样，结果取决于读的那一步。

⚠️ 同一个机制还有一个后果：b[[0,0,0]] += 1 只加一次，不是三次。 那一条以及 np.add.at 的用法在 06 章第五节。

💀 五、事故：拿切片当 K-means 的初始中心

判据讲完了，看它在真代码里长什么样。下面这段 K-means 除了初始中心的取法之外，两版一个字符都不差：

先看这个关系：X[:3] 与原数组共享内存，X[[0, 1, 2]] 得到独立拷贝。展开实验后，重点找初始化与 C[j] = … 的就地更新；结果与事故解释保留在代码下方。

查看 K-means 完整实验 · 数据生成、两种初始化与结果比较 
import numpy as np

np.set_printoptions(precision=3, suppress=True)


def kmeans(X, C, iters=10):
    """标准 K-means。C 是调用者传进来的初始中心，函数会就地更新它"""
    for _ in range(iters):
        d = ((X[:, None, :] - C[None, :, :]) ** 2).sum(-1)   # (n, k)，第 03 章那个模式
        lab = d.argmin(1)
        for j in range(len(C)):
            if (lab == j).any():
                C[j] = X[lab == j].mean(0)                   # ⭐ 就地写进 C
    return C, lab


rng = np.random.default_rng(0)
X0 = np.vstack([rng.normal([0, 0], .5, (60, 2)),
                rng.normal([5, 0], .5, (60, 2)),
                rng.normal([0, 5], .5, (60, 2))])          # 三坨，各 60 个点

# ❌ 用基础切片挑初始中心 —— C 是 X 的视图
X = X0.copy()
init = X[:3]
print("X[:3]     和 X 共享内存吗:", np.shares_memory(X, init))
C_bad, lab_bad = kmeans(X, init)
print("跑完之后 X 被改掉了", (X != X0).any(axis=1).sum(), "行 / 共", len(X), "行")
print("  第 1 行  原本", X0[1], " 现在", X[1], " <- 从第一簇被搬到第二簇的位置上了")

# ✅ 用花式索引挑 —— 天然就是拷贝
X = X0.copy()
init = X[[0, 1, 2]]
print("\nX[[0,1,2]] 和 X 共享内存吗:", np.shares_memory(X, init))
C_ok, lab_ok = kmeans(X, init)
print("跑完之后 X 被改掉了", (X != X0).any(axis=1).sum(), "行")


def inertia(X, C, lab):
    return ((X - C[lab]) ** 2).sum()


print("\n拿【原始数据】评两版的簇内平方和:")
print("  错版 inertia = %.3f" % inertia(X0, C_bad, lab_bad))
print("  对版 inertia = %.3f" % inertia(X0, C_ok, lab_ok))
print("  两版标签一致的样本 =", (lab_bad == lab_ok).sum(), "/", len(X0))

a += 1

# ---- 同一件事发生在函数参数上 ----
def center_inplace(x):
    x -= x.mean()             # ⚠️ 原地：调用者的数组被改了
    return x

def center_pure(x):
    x = x - x.mean()          # ✅ 新数组：调用者不受影响
    return x

d = np.array([1., 2., 3.])
center_inplace(d)
print("\ncenter_inplace 之后 调用者的 d =", d, " <- 被改了")

center_pure(d)

# ---- 数值梯度检查：站内那两行 .copy() 是承重的 ----
def loss(w):
    return (w ** 2).sum()

W = np.array([3.0, 4.0])
eps = 1e-5

Wp = W.copy(); Wp[0] += eps          # ✅ 站内 ml_md/08:207-208 的写法
Wm = W.copy(); Wm[0] -= eps
print("\n带 .copy()  数值梯度 =", (loss(Wp) - loss(Wm)) / (2 * eps), " 解析值 = 6.0")

W = np.array([3.0, 4.0])
Wp = W; Wp[0] += eps                 # ❌ 少写了 .copy()
Wm = W; Wm[0] -= eps
print("少 .copy()  数值梯度 =", (loss(Wp) - loss(Wm)) / (2 * eps), " <- 恒等于 0，不报错")
print("            Wp is W:", Wp is W, "  Wm is W:", Wm is W, "  三个名字同一个数组")

⭐ a.copy() ✅ 默认选它 —— 意图写在脸上，读代码的人一眼看得懂

🚦 八、函数边界上的三条约定

上面两场事故都发生在函数边界上 —— 一个函数改了调用者的数组，而调用者不知道。 三条约定能挡住绝大部分：

# 约定 怎么落地
① 会改参数的函数，要把这件事写进名字或第一行文档 def center_inplace(x) / """就地修改 x"""。⭐ NumPy 自己就是这么做的：np.sort(a) 返回新的，a.sort() 改自己
② 要改就先在入口拷一份，别在半路拷 x = np.array(x, dtype=float) 放函数第一行。⚠️ 别写 np.asarray，它不拷
③ ⭐ 不要把内部数组的视图当返回值交出去 return self._buf[1:] 会让调用者拿到一把能改你内部状态的钥匙。要么 .copy()，要么 r.flags.writeable = False 把它设成只读

⚠️ 约定 ③ 那个只读的招数你已经见过：03 章第三节里 np.broadcast_to 返回的东西 writeable 是 False，就是 NumPy 自己在用这一手。

👀 答案

  1. 切片版 b = [1 1 3 3 5 5]（原数组变了），花式索引版 b = [0 1 2 3 4 5]（没变）。

    根源是 np.shares_memory(b, b[::2]) 是 True、np.shares_memory(b, b[[0,2]]) 是 False —— 切片给视图（同一块内存的另一种读法），花式索引给拷贝。

    ⚠️ 两行都不报错、都返回一个正常数组，差别只在背后是不是同一块内存。

  2. np.shares_memory(a, b)。.base 两个方向都会错：

    ① 共享却判成不共享 —— .base 不指向上一层而是最终持有内存的那个，所以 a.T.base is a 是 False；

    ② 不共享却判成共享 —— a.T.reshape(12) 和 a[1:3, [0,2]] 的 .base 都不是 None（指向过程中造出的临时拷贝），而 shares_memory 是 False。

    所以 if x.base is not None 这个写法不能用。

  3. a.T.base is a 是 False（直觉会以为 True），a.T.base is base 是 True。只有当源数组自己就是内存持有者（b.base is None）时，c.base is b 那种写法才成立 —— 完整机制在 05 章第三节。

  4. reshape（还有 ravel）：a.reshape(4,3) 共享内存，a.T.reshape(12) 不共享 —— 是否能给视图取决于目标形状能否由当前 strides 表达；不连续不等于必然拷贝。想保证不共享写 flatten()，它一定拷贝；ravel() 会尽量给视图。

  5. 因为判据是「那个下标在不在等号左边」，和视图/拷贝是两件独立的事。

    c = b[[0,2]] 走 __getitem__，抄一份给你；b[[0,2]] += 1 走 __setitem__，按下标直接往 b 里写：先读取、计算，再写回；读取过程中仍可能产生临时数组。

    实跑 b[[0,2]] += 1 之后 b = [1 1 3 3 4 5]。一句话：只有紧挨着等号左边的那个下标才是写，它左边的每一步都是读。

  6. 💀 既不报错、也不生效：a[[0,1]] 先当 __getitem__ 跑完造出一份临时拷贝，[0] = 99 写进那份拷贝，然后拷贝被回收 —— 实跑 a[0] 还是 [0 1 2 3]。比报错糟，是因为它连一行错误信息都不给你。

    正确写法是合并成一次下标：a[[0,1], 0] = 99（实跑 a[:, 0] = [99 99 8]）。

    ⚠️ a[0][1] = 99 反而生效，因为 a[0] 恰好是视图 —— 语法一样，结果取决于读那一步给的是什么。

  7. X 被改掉 3 行（180 行里的前 3 行，被覆盖成了聚类中心；第 1 行从 [0.32, 0.052] 被搬到 [4.86, 0.014]，跨了一个簇）。错版 inertia 133.080，对版 89.828。

    ⚠️ 重点是「178/180 个标签一样」：结果看起来只像「这次收敛得不太好」，没有报错、没有 nan、没有形状异常，所以没人会去怀疑那一行 X[:3] —— 而被污染的是数据本身，后面每个用到 X 的模型都在用它。

  8. 恒等于 0.0。因为 Wp is W 和 Wm is W 都是 True，三个名字是同一个数组：+eps 之后紧接着 -eps，两次前向算的是同一个点。

    事后看不出来是因为加完又减完正好抵消，实测 W[0] == 3.0 是 True —— 连现场都没留下。

    ⚠️ 典型的排查路径是去逐行核对反向传播公式，而那边根本没错。站内 ml_md/08:207-208 和 附录C:71-72 都老实写了 .copy()，那是承重的。

  9. 切断的：a.copy() （默认选它，意图最清楚）、np.copy(a)、np.array(a)（copy 默认 True）、a.astype(dt)。

    不切断的：⚠️ np.asarray(a)（职责是「保证是 ndarray」，不保证独立）、💀 a[:]（那是 Python list 的习惯，对 ndarray 给的是视图）。

    NumPy 2.x 里 np.array(x, copy=False) 从「能不拷就不拷」变成了「不许拷，做不到就抛 ValueError: Unable to avoid copy while creating an array as requested.」；想要老语义写 np.asarray(x)。

  10. ① 把「会改参数」写进函数名或第一行文档（NumPy 自己就是：np.sort(a) 返回新的、a.sort() 改自己）；

    ② 要改就在函数第一行拷一份 x = np.array(x, dtype=float)（⚠️ 别写 np.asarray，它不拷）；

    ③ 别把内部数组的视图当返回值交出去 —— 要么 .copy()，要么 r.flags.writeable = False 设成只读（np.broadcast_to 就是这么干的）。

    拷贝不免费：122 MB 的数组取视图 0.0001 ms、.copy() 10.1 ms，约 9 万倍，所以入口撒一次就够，别在循环里每行撒。

⚡ 走神救援

  • 判断两个 ndarray 的数据缓冲区是否共享，用 np.shares_memory(a, b)，不要用 .base 代替。
  • 花式索引读出的结果是拷贝；直接向原数组下标赋值仍会写回。链式索引可能只改到临时拷贝。
  • K-means 实验只污染 3 行，却有 178/180 个标签相同；梯度检查少了独立拷贝，差分会变成 0。
  • 需要独立数值缓冲区时用 .copy()；dtype=object 里的对象另需深拷贝。函数边界上的约定见第八节。
