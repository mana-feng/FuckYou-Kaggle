🧭 怎么用这一页

这个板块从头到尾只做一个应用：EmployeeHub（员工管理工具）。 所以这份速查也按那条主线组织 —— 数据 → 页面 → 逻辑 → 权限 → 集成 → 交付，你卡在哪一段就查哪一段。

🧱 二、四个反复会遇到的词

词 一句话 底下其实是什么
Entity 一类业务对象（员工、部门），带一组属性 数据库里的一张表
关系 两个 Entity 之间的连线，比如「一个部门有很多员工」 外键。⚠️ 画错了后面页面和逻辑都会别扭
属性 Entity 上的一个字段 表的一列
Microflow 用图形画出来的一段业务逻辑：取数据 → 判断 → 改数据 → 给提示 手写后端里的一个接口处理函数

⭐ 02 章那条判据值得单独记：画之前先问「这到底该建成 Entity、属性，还是关系」—— 最常见的坑是把部门写成一段自由文字，以及把所有东西都做成 Entity。

🔐 三、权限：三层边界

层 管什么 ⚠️ 只做这一层会怎样
模块角色 / 用户角色 谁属于哪一类人 分了角色但没配后面两层，等于没分
实体访问权 这类人对这个 Entity 能读 / 能改哪些属性 ⭐ 这一层才是真正拦住数据的那一层
页面与按钮可见性 界面上给不给他看到入口 💀 按钮不见了不等于动作不能发生 —— 这是最常见的误解

📋 上线前有一个「五分钟权限演练」：拿另一个角色的身份，去试那些不该做的事。 ⭐ 判据不是「按钮还在不在」，是「动作能不能真的发生」。

🚦 四、交付：三种「能跑」

哪一种 意思 还差什么
我这里能跑 本地 Studio Pro 里跑起来了 别人拿不到
环境里能跑 部署到某个环境、能访问 数据、权限、集成配置未必对
⭐ 别人能安全地用 权限对、数据对、出问题能查、能交接 这才是「交付」

交接给别人时至少留四样东西（见 07 倒数第二节）—— ⚠️ 别把「版本」当成文件名，那一章专门讲了这件事。
