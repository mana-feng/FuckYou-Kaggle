01 · 第一次打开 Studio Pro：先让它跑起来

⏱ 14 分钟 ｜ 不理解全部面板，也能开始

🎯 一句话

Studio Pro 是你搭 Mendix 应用的桌面工作台；第一步不是研究所有按钮，而是确认你能创建、运行并看到一个项目。

🧭 你眼前的四块东西分别干什么

你看到的地方 先把它当成 现在要不要深究
App Explorer 应用的文件树 要：以后所有东西从这里找
编辑区 你正在画的页面或流程 要：今天主要看这里
Properties 当前选中东西的设置面板 够用时再改
Console 应用运行时的消息 出错时才重点看

官方快速入门也是用 Studio Pro 建一个员工数据 Web 应用：先创建项目，再用绿色运行按钮本地启动。你现在只需要得到一个最小的成功信号：浏览器里真的打开了应用。

🚦 今天的最小动作

1 · 新建一个空应用
  • 起一个你看得懂的名字，例如 EmployeeHub。
  • 不用急着选一堆模板；目标是看懂最小项目。
2 · 按运行
  • 让 Studio Pro 在本机启动应用。
  • 浏览器打开后，先确认页面能出现。
3 · 只观察，不要乱改
  • 在 App Explorer 找到主模块。
  • 记住：以后数据、页面、流程都会放进模块里。

如果运行失败，先不要把错误当成“我不会”。把它分成两类：环境没准备好，或是项目配置有问题。第一天大多数问题属于前者；先按提示补全 Studio Pro 所需组件，别跳进业务逻辑里排查。

🧪 跟着做：从零到看到第一张页面

不同版本的按钮文字和模板名称可能略有不同；下面记住的是动作顺序，不是死记菜单位置。

第 1 步：创建项目

  1. 打开 Studio Pro，选择创建新应用。
  2. 给应用取名 EmployeeHub。这个名字之后会出现在项目、应用和部署记录里，先取清楚比取酷更重要。
  3. 选择官方提供的入门或空白 Web 应用模板即可。暂时别挑复杂行业模板：里面已有太多你还不认识的东西。
  4. 选一个自己找得到的本地目录，等项目创建完成。

你应该看到： 左边出现 App Explorer；里面至少有一个模块，通常还会有导航、配置和系统模块。看不懂名字没关系，这不是报错。

第 2 步：先认识“模块”

把模块想成一个带标签的抽屉。我们这次会把“员工管理”相关的东西放在同一个抽屉里：员工数据、员工页面、保存员工的流程，彼此更容易找到。

现在只做一件事：在 App Explorer 中找到你的主模块，右键或展开它，确认里面能新建 Domain Model、Page、Microflow。不要一次创建三个空东西；知道入口在哪就够了。

第 3 步：运行最小项目

  1. 点击顶部绿色运行按钮。
  2. 等待 Console 出现启动信息。第一次可能比以后慢，因为需要准备本地运行环境。
  3. Studio Pro 通常会打开浏览器；如果没有自动打开，留意 Console 给出的本地地址。
  4. 浏览器出现任何能用的初始页面，就算成功。它丑、内容少、英文，都不影响这一步完成。

成功标准不是“像产品”，而是： 你能在浏览器打开页面，并且 Console 没有持续滚出红色错误。

第 4 步：故意做一次小观察

回到 Studio Pro，在 App Explorer 中点一个已有页面。编辑区会显示页面的结构；再点页面里任意一个控件，右侧 Properties 会变。

你不需要改任何值。只要观察到“我选中什么，Properties 就在描述什么”，以后就不会把右侧面板当成神秘设置墙。

🧯 卡住时：先按这个顺序排查

你看到的情况 先做什么 别急着做什么
运行按钮灰色或点了没反应 保存项目，观察 Console 最后一条信息 不要反复重装整个项目
浏览器没打开 在 Console 找本地地址，复制到浏览器 不要以为项目一定没运行
有红色错误 只读第一条红色错误，找它提到的对象或设置 不要从最后一条错误开始猜
浏览器打开但页面空白 回到 Studio Pro，确认运行进程没有停止 不要马上重画页面
模板里的英文看不懂 先看图标和对象类型；词不懂可以点术语速查 不要因此跳过整个步骤

一个很实用的习惯：每次遇到错误，先截一张图，再只改一件事。这样改坏了也知道从哪一步开始坏的。

🧷 这一步以后，你知道的东西够做什么

你还不会做应用，但你已经有了最重要的反馈环：

在 Studio Pro 改模型、页面或流程
→
按运行让应用重新启动或刷新
→
在浏览器看判断结果是否符合预期

后面每一章都按这个循环。低代码不是“不需要检查”，而是你把原本写在代码里的结构改成图形后，依然要用运行结果验证它。

🧠 “运行”到底发生了什么

你画出来的模型和页面不是截图。运行时，Mendix 会把它们组合成一个 Web 应用：浏览器负责展示；应用负责处理点击和数据；本地环境暂时负责保存和运行。

所以每次完成一小步，都建议按一次运行：

  • 早发现错误，错误范围很小；
  • 每次看到变化，知道这一步到底改变了什么；
  • 不会积累十个改动后才发现哪里坏了。

🛑 可以停在这里

✅ 检查点

为什么不要等“全做完”才第一次运行？

👀 看答案

因为早运行能把问题限制在刚刚那一步。你也能立刻看见修改和页面效果的对应关系，不会在一大堆改动里猜哪里出错。

⚡ 走神救援

  • Studio Pro 是工作台，浏览器是成品预览。
  • App Explorer 是应用的目录树；模块是功能抽屉。
  • 第一目标不是学会所有面板，而是成功运行一次。
  • 下一步：决定员工和部门怎么保存。
